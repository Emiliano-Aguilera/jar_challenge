## The challenge

A Yahboom ROSMASTER X3 (mecanum, ROS 2 Humble) receives a known maze map on `/map`, finds N red boxes
("víctimas"), reports their centers on `/victimas`, optionally returns to start and publishes `/done`.
Fully autonomous. Rosario: qualification Wed 2026-11-04 (2 runs, best counts, top 4 advance); final
Thu 2026-11-05 17:00 (1 run, new layout). Delivery cutoff: unknown (asked to the organizers).

## Run protocol (§5, §11)

1. Organizers deploy the latest green-CI commit on a track station networked to the robot and run
   `ros2 launch equipo_jar competencia.launch.py victimas:=N` (default N = 5; sim adds `use_sim_time:=true`).
2. Until `/map` arrives: no non-zero `/cmd_vel`, no reports, launch stays alive.
3. `/map` publication = t0 of a 10 min clock. Robot placed by hand near the origin; tolerance and yaw unspecified.
4. Run ends at the first of: `/done`, 10 min, 60 s without translation or rotation, referee call
   (tip-over, leaving the maze, force majeure). The practice judge counts as still anything below
   0.02 m/s and 0.05 rad/s on `/odom`.
5. Software crash: no restart, clock keeps running. Organizer fault: run is repeated.

## Scoring (§7.2, §8)

| Event | Points |
| --- | --- |
| Report ≤ 0.25 m / ≤ 0.50 m / > 0.50 m from the box center (floor projection, `map` frame) | +100 / +50 / 0 |
| Fast bonus: all N victims scored with reports sent before 300 s (`/done` may come later) | +200 |
| `/done` within 0.25 m of the start pose, with ≥ 1 victim scored | +100 |
| Each collision with anything (walls, obstacles, any box) | −50 |
| Leaving the maze (also ends the run) | −50 |
| Tip-over > 45° | run = 0 |

Floor 0. Max 100·N + 300. Tie-break: shorter total time (t0 → `/done` or stop), fewer collisions, then
(qualification) the other run.

- Exactly N reports, counted in arrival order; extras ignored. Malformed ones (`frame_id != map`, NaN/inf)
  still consume one. A report on a distractor loses a victim and the fast bonus → report only confirmed candidates.
- Each report goes to its nearest victim within 0.5 m; each victim keeps its best report.
- The visible face is 0.125 m from the center: localization error + center-estimate error must stay < 0.25 m.
- Build reports only with `armar_reporte(x, y, ahora)` (`src/equipo_jar/equipo_jar/reportes.py`).
- After `/done`: stop, never move again. While moving, publish `/cmd_vel` at ≥ 10 Hz (robot stops after 0.5 s of silence).
- `tools/puntaje.py` is the organizers' practice interpretation (its fast bonus also requires wasted reports
  before 300 s). The official judge is private.

## Official interface (§7.1) — cannot be modified or extended

| Topic | Direction | Type | QoS |
| --- | --- | --- | --- |
| `/map` | judge → team | `nav_msgs/OccupancyGrid` | reliable + transient local, depth 1 |
| `/victimas`, `/done`, `/cmd_vel` | team → judge / robot | `PointStamped`, `Empty`, `Twist` | reliable (ROS default) |
| `/scan`, `/cam_1/color/image_raw`, `/cam_1/color/camera_info`, `/cam_1/depth/color/points` | robot → team | LaserScan, Image, CameraInfo, PointCloud2 | **best effort**: subscribe with `qos_profile_sensor_data` |
| `/odom`, `/imu/data`, `/tf`, `/tf_static` (+ `/joint_states`, allowed by the template) | robot → team | standard | reliable (`/tf_static` transient local) |

- QoS mismatch = silent: a reliable subscriber on a best-effort topic receives nothing. Details: `docs/QOS.md`.
- Team nodes publish only on `/victimas`, `/done`, `/cmd_vel`, `/tf`, `/tf_static`. Never on `/map`
  (no Nav2 `map_server`, no SLAM output on `/map`).
- Every other platform topic is forbidden, e.g. `/imu/data_raw`, `/cam_1/depth/image_raw`, `/scan_filtered`,
  `/ground_truth/*`, `/internal/*`, `cmd_vel_gz`, Gazebo topics. Internal team topics: prefix `/equipo/`.

## Robot and arena facts (physical X3, from simulator `real_robot_contract.yaml` @ `jar2026-v1`)

- LiDAR: 1080 rays/360°, 0.05–12 m, ~7.2 Hz, ~136 ms latency, ~25% rays non-finite. `laser_link` is
  mounted with yaw = π: always use TF, never assume ray 0 points forward.
- RGB: 320×240, fx = fy ≈ 271.8, cx ≈ 158.7, HFOV ≈ 61°, 30 Hz, `cam_1_color_optical_frame`, ≈ 0.107 m above floor.
- Depth: valid only ≥ 0.6 m, ~38% valid pixels; cloud (`cam_1_depth_frame`) ~8 Hz, gaps up to ~1.1 s. Unreliable.
- `/odom` (child `base_footprint`) and `/imu/data`: 10 Hz. `/cmd_vel` limits 1.0 m/s (x, y), 5 rad/s.
  Wheelbase 0.16 m, track 0.17 m.
- Boxes (sim): 0.25 × 0.25 × 0.30 m. Victims red; distractors blue/yellow/green/neutral, never red;
  decoys are physical obstacles absent from `/map`.
- Practice maps (6, 0.05 m/cell, ~6 × 6 m): boxes are NOT drawn in `/map`, N = 2–3, blue boxes are the
  distractors, no decoys, nearest wall to origin ≈ 0.43 m. Whether the competition `/map` omits boxes is unconfirmed.

## CI and delivery traps (verified by running `tools/` on 2026-10-15)

Fail CI:
- In `src/` code: `ground_truth`, `/internal/`, `cmd_vel_gz`, Gazebo topics or `gz`/`ign` CLI.
- Anywhere in the repo except `build/`, `install/`, `log/`: `.pgm`, `.world`, `.sdf`, a map_server YAML
  (`image:` + `resolution:`), any file > 50 MB (rosbags).
- `params/`: numeric lists ≥ 4 items (e.g. Nav2 `collision_monitor` polygon `points`, 6-value HSV ranges) or
  > 12 items, nested lists; leaf names containing `victim`, `coord`, `spawn`, `posicion_` or ending in
  `waypoint(s)`; strings ending in `.yaml/.png/.pgm/.world/.sdf` or containing `maze`/`laberinto`. An AMCL initial pose is allowed.
- Runtime: wrong QoS; publishing on a robot/judge topic; using a non-§7.1 topic the platform also uses;
  motion or reports before `/map`; a malformed report; the launch dying (also in the offline Docker image after 25 s).
  The auditor only sees what exists 6–12 s after launch; the official run records everything.

Flagged for manual review by the technical judge (avoid):
- A variable named `*victim*|*waypoint*|*checkpoint*|*ruta*` initialized with a literal list/dict/tuple
  (`self.victimas_detectadas = []` → use `self.detecciones = []`).
- 3+ literal coordinate pairs (includes the Nav2 `footprint` string → use `robot_radius`).
- Practice world names (`maze_1`, `laberinto_`) in `src/`. Trained models that encode arena geometry (§10).

Delivery:
- Only `src/equipo_jar/params/` may change after the cutoff → every tunable (speeds, HSV bounds as separate
  scalars, thresholds, inflation) must be a named param. N comes only from `victimas:=N`.
- Dependencies: ROS packages as `<exec_depend>` in `package.xml` (rosdep); pip packages pinned in
  `requirements.txt`. The image runs with `--network none`.
- New nodes need a `console_scripts` entry in `setup.py`; extra data files (e.g. Nav2 BT XML) need a
  `data_files` entry. Only top-level `params/*.yaml` and `launch/*.launch.py` are installed today.
- Delivery PR (fork → upstream `main`): title `[Equipo] <nombre>`, `equipo.yaml` filled, no personal data.
  Its CI runs without `--template`, so placeholders fail there. A PR touching `tools/` or `.github/`
  is not published to the practice leaderboard.
- CI simulation runs only 90 s after `/map`, on `maze_1_6x5` and `maze_3_6x6`: a smoke test, not a benchmark.

## Commands (Linux: they need `setsid` and Gazebo Fortress)

Scripts set `ROS_DOMAIN_ID=77` and `ROS_LOCALHOST_ONLY=1`; match them in manual terminals.

```bash
source /opt/ros/humble/setup.bash && colcon build --base-paths src && source install/setup.bash
tools/verificar.sh --template                    # CI checks without simulator (allows equipo.yaml placeholders)
tools/verificar.sh                               # as in the delivery PR
tools/verificar.sh --template --sim maze_1_6x5   # + one sim run (yahboom_rosmaster built and sourced)
tools/correr_simulador.sh maze_2_6x5 600         # full 10-min headless run + scoring → build/verificacion/<map>/
SIM=$(ros2 pkg prefix --share yahboom_rosmaster_gazebo)
python3 tools/juez.py --mundo maze_1_6x5 --mapa $SIM/maps/maze_1_6x5.yaml --ground-truth   # judge only
docker build -t equipo-jar . && docker run --rm --network none -e VICTIMAS=3 equipo-jar
```

- `juez.py` only judges: start the sim and the team launch yourself. Collisions and exits count only when
  someone calls `/juez/colision` or `/juez/salida`, so CI and leaderboard scores ignore collisions.
- Start offset (practice hand placement) exists only on the sim launch: `spawn_x:=0.15 spawn_y:=-0.1 spawn_yaw:=0.2`.
  `correr_simulador.sh` cannot pass it.
- Practice worlds: `maze_1_6x5`, `maze_2_6x5`, `maze_3_6x6`, `maze_4_metal_6x6`, `laberinto_1`, `laberinto_simple`.

## Git workflow

1. Integration branch: `desarrollo` (from `main`). Nobody commits directly to `desarrollo` or `main`.
2. New task: `git switch desarrollo && git pull`, then branch `<module>-<task>` (e.g. `navegacion-movimiento`).
3. Small changes. Before the PR: build, `tools/verificar.sh --template` (or the fork CI), and test in simulation.
4. PR `<module>-<task>` → `desarrollo`. Merge only with green CI, working in sim and one teammate's review.
   Every merge wires its node into `competencia.launch.py` (or keeps it out if unfinished): `desarrollo`
   must always build, launch and score.
5. Branches live 1–3 days; delete after merge; pull `desarrollo` into your branch often.
6. Commit messages: `<module>: <what changed>` plus a body line with the why. Git history is the team log.

## Rules for agents (and humans)

- Never commit, push, merge or open PRs unless your user asks. Never force-push shared branches.
- Never touch `tools/` or `.github/`. No agent attribution in commits or PRs (no `Co-Authored-By`, no "Generated with");
  `.claude/settings.json` enforces this for Claude Code.
- All text (commits, PRs, comments, docs, logs, messages): as simple and short as possible, plain words,
  but technically precise. Simple wording, same technical level.
- Touching another module's files or a shared file (launch, `package.xml`, `setup.py`, `Dockerfile`, interfaces): ask first.
- At session start: `git fetch`, confirm you are on a task branch (not `desarrollo`/`main`), skim recent commits.
- Many members are new to git, ROS 2 and agents: explain what you do and why, in plain words.
